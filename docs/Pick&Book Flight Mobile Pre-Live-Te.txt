8. Safe Cashfree Cancellation Behavior & Decision Table
Critical Backend Discovery on CancelOrder

In PaymentService.cs#L229-L245 and CashfreePaymentController.cs#L1457: POST /api/cashfree/orders/{orderId}/cancel marks the payment Failed locally and immediately releases the hybrid wallet hold. If a customer initiated a UPI transaction, closed the SDK, and Mobile calls /cancel while the bank payment is still clearing, the wallet hold is released. When Cashfree later sends a SUCCESS webhook, line 225 logs an inconsistent state and refuses to commit the wallet hold, leaving the payment orphaned!

9. Round-Trip and Multi-City Support Boundary
Supported Journey Types for Mobile Phase 1:
JourneyType: "1" (One-Way): Fully supported.
JourneyType: "2" (Round-Trip - Same Trace): Fully supported when both legs originate from the same search TraceId. Comma-separated ResultIndex (e.g. "1_SAMPLE_ONWARD,1_SAMPLE_RETURN") is supported.
Blocked Combinations:
Split-Trace Round Trips (Different Airlines / Traces): STRICTLY BLOCKED. Upstream TicketLCCRawAsync accepts only one TraceId as an integer/string. Attempting to pass legs from two different TraceIds causes supplier rejection or leaves one leg un-ticketed. Mobile must block split-trace round-trip selection in Phase 1.
Multi-City (JourneyType: "3"): Supported only if all legs share a single combined SRDV Multi-City TraceId. Split-trace multi-city is blocked.
Persisted Record:
Combined round trips persist onward PNR in FlightReservation.Pnr and return leg PNR in FlightReservation.ReturnPnr.
10. Partial Cancellation & Quote Limitations
Authoritative vs Estimated Quotes:
POST /api/flight/srdv/GetCancellationCharges accepts only TraceId and PNR. It cannot quote an arbitrary subset of passengers or sectors in advance.
If the supplier returns live charges, it is for the entire PNR or segment.
If the supplier returns dynamic policy text, Mobile must explicitly label the displayed refund as "Estimated" and display:
"Final refund amount will be confirmed after airline penalty calculation."
Execution Contract:
POST /api/flight/srdv/SendChangeRequest accepts exact TicketData (array of {TicketId, FirstName, LastName}) and Sectors.
Backend marks IsPartialCancellation = true if TicketData.Count < reservation.SeatsBooked or Sectors.Count < reservation.Segments.Count.
The authoritative final refund is calculated by FulfillmentRecoveryWorker and recorded in FlightCancellationRequest.CustomerRefundAmountInr and BookingCancellation.CustomerRefundAmount.

16. Mobile Decision Tables
1. Payment & Checkout Decision Table
Create-Order Response Received: Store cashfreeOrderId and paymentSessionId. Launch Cashfree Native SDK.
Network Drop during Create-Order: Retry create-order with the same IdempotencyKey.
User Closes SDK Modal:
If user did not attempt payment: Call POST /api/cashfree/orders/{orderId}/cancel to release wallet hold.
If user launched UPI / Netbanking: Do not cancel. Call GET /api/cashfree/orders/{orderId}/payments.
SDK Reports Success: Call GET /api/cashfree/orders/{orderId}/payments.
Verification Returns Status == "Pending": Continue polling every 5 seconds (up to 2 minutes).
Verification Returns FulfillmentStatus == "InProgress": Show "Confirming with Airline...". Poll every 5s.
Verification Returns FulfillmentStatus == "Success": Transition to Confirmed screen.
Verification Returns FulfillmentStatus.StartsWith("Failed"): Show "Booking Failed - 100% Refund Processing".
2. Booking Confirmation Decision Table
"Payment Received": When payment.Status == "Success".
"Confirming with Airline": When payment.Status == "Success" AND fulfillmentStatus == "InProgress".
"Booking Confirmed": Only when fulfillmentStatus == "Success" AND PNR is populated. (Never display confirmed based on Cashfree success alone).
"Ticket Issued": When TicketNumber is present.
"Booking Failed - Full Refund Processing": When fulfillmentStatus == "Failed_SupplierError" or "Failed_PriceChanged".
3. Cancellation Decision Table
"Cancellation Requested": When SendChangeRequest returns Status: 1 (Pending).
"Cancellation Processing": When GetCancelStatus returns CancellationStatus == "Pending" or "IN_PROCESS".
"Partially Cancelled": When MyBookings reflects specific passengers cancelled while others remain Booked.
"Fully Cancelled": When all passengers are cancelled and reservation status is Cancelled.
"Cancellation Rejected": When GetCancelStatus returns CancellationStatus == "Rejected" (Status 4). Show: "Cancellation rejected by airline. Tickets remain active."

18. Remaining Backend Limitations
SSR Item Price Validation: SSR prices are summed from client JSON without server re-verification against the supplier catalog.
Pre-Payment Passenger Age Check: Passenger validation runs downstream at ticketing rather than inside create-order.
Nationality Field in Ticketing: Nationality is omitted in TicketLCCRawAsync.
Idempotency Key Payload Check: Reusing an idempotency key with an altered booking payload echoes the previous order instead of returning a 409 Conflict.
Database Index Uniqueness: PaymentReference index is non-unique in MySQL.
